# Работа с мессенджером

Мессенджер — файл `MESSENGER.md` в корне проекта. Список задач — `TODO.md`.
Участники: **Ник** (разработчик) и **Наставник** (даёт задания и обратную связь).

## Кто пишет

Перед ответом определи, от чьего имени ты пишешь:
- работаешь с разработчиком проекта → подпись `Ник`;
- работаешь с тем, кто ставит задания и проверяет работу → подпись `Наставник`.

Если из разговора это непонятно, один раз спроси у пользователя.

## Прочитать

1. Сначала подтяни свежую версию: `git pull` (если репозиторий настроен и нет локальных изменений, которые помешают).
2. Прочитай `MESSENGER.md` и `TODO.md`.
3. Новые сообщения — это все сообщения другого участника после последнего сообщения текущего пользователя.
4. Покажи пользователю:
   - новые сообщения дословно (дата, автор, текст), а если новых нет, то так и скажи;
   - кратко: какие задачи из `TODO.md` сейчас в работе.
5. Если в сообщении есть задание, предложи взяться за него, но сам не начинай.

## Ответить

1. Сначала выполни шаги «Прочитать», чтобы ответ учитывал последние сообщения.
2. Если пользователь дал текст ответа, используй его по смыслу и сохрани его тон. Если не дал, составь черновик по текущей ситуации (что сделано, вопросы, ссылки на файлы и строки) и покажи пользователю до записи.
3. Добавь сообщение **в самый низ** `MESSENGER.md`, отделив его пустой строкой:

   ```
   ### YYYY-MM-DD · <Имя>
   Текст сообщения
   ```

   Дата — сегодняшняя. Старые сообщения не редактируй и не удаляй.
4. `TODO.md`:
   - **Ник** не отмечает задачи сам. О готовности задачи он пишет в сообщении.
   - **Наставник** при необходимости переносит принятые задачи в «Выполнено» (`[x]`) и добавляет новые в «В работе».
5. Предложи закоммитить и запушить изменения, чтобы собеседник их увидел. Без согласия пользователя не пушь.
